## 项目概览

HealthAI-Platform 是一个**企业级健康智能体平台**，核心是基于 **LangGraph 状态机编排的 RAG（检索增强生成）管道**，提供健康问答、个性化饮食计划生成、饮食记录、安全护栏等功能。

**技术栈**：
- 后端框架：FastAPI + Pydantic v2 + SQLAlchemy 2.0
- 数据存储：PostgreSQL 15 + ChromaDB 1.5 + Redis 7
- AI 能力：LangChain 1.3 / LangGraph 1.2 / ZhipuAI GLM-4 / Embedding API / Whisper
- 可观测性：OpenTelemetry + Jaeger + Prometheus + Grafana
- 部署：Docker Compose 8 服务编排

**架构分层**（依赖单向，不循环）：
```
api/         ← 路由层（接收请求）
  ↓
services/    ← 业务层（核心逻辑）
  ↓
core/        ← 引擎层（RAG 管道）
  ↓
repositories/ ← 数据层（CRUD）
  ↓
models/      ← 模型层（ORM 定义）
```

### 2.1 api/ API 层

```

│   ├── tracing.py               # 分布式追踪中间件：为每个请求建 root span，提取入站 traceparent，注入 X-Trace-Id 响应头
│   └── version_control.py       # API 版本控制：prefix 绑定版本、注入 X-API-Version、未带版本重定向到最新稳定版
│
├── routes/                      # 路由层（按业务领域拆分）
│   ├── __init__.py
│   ├── auth.py                  # 认证路由：注册(用户名/邮箱+验证码)、登录、刷新Token、改密、忘记密码、安全问题
│   ├── diet.py                  # 饮食记录路由：自然语言饮食解析、食物搜索、饮食日志 CRUD
│   ├── feedback.py              # 用户反馈路由：点赞/踩/使用计划、反馈列表、偏好查询
│   ├── plan.py                  # 饮食计划路由：生成、列表、详情、更新、删除、打卡记录
│   ├── rag.py                   # RAG 路由：同步/流式查询、文档入库、管道状态检查
│   ├── user.py                  # 用户档案路由：获取/更新档案、TDEE 与宏量营养素计算
│   └── v2.py                    # V2/V4 预留路由占位（深度个性化推荐、多模态、版本链），返回 501
│
└── schemas/
    └── __init__.py              # Pydantic schema 占位（模型定义在 db_models.py 与各路由内）
```

**设计要点**：
- 路由按业务领域拆分（auth/diet/feedback/plan/rag/user），符合 RESTful 规范
- 中间件独立目录，职责单一（监控/追踪/版本控制各司其职）
- SSE 流式响应抽成独立工具，可被多个路由复用

### 2.2 core/ RAG 核心引擎

```
src/core/
├── __init__.py
├── graph_builder.py             # 【核心】LangGraph 状态机编排：节点注册+普通边+条件边(意图分流/评估循环/追问分流)
│                                  流程：START→安全护栏→意图识别→Query改写→(SQL/向量/混合)→评估→fusion→生成→END
├── safety_checker.py            # 【核心】安全护栏：正则规则+LLM 语义双重校验，拦截处方药/诊断/极端饮食等，规则外置热更新
├── state.py                     # RAGState TypedDict 定义：图状态 schema（含 reducer 合并函数 _merge_lists/_merge_errors）
├── rrf_fusion.py                # RRF 倒数排名融合：多路向量检索+跨源(SQL/向量)统一排序，公式 score=Σ1/(k+rank)
├── llm_client.py                # LLM 客户端封装：统一 HTTP API 调用接口，兼容 OpenAI/通义千问/本地模型
├── embedding.py                 # ZhipuAI Embedding 函数：兼容 ChromaDB EmbeddingFunction 协议，批量分批处理
├── guideline_registry.py        # 【核心】权威食养指南注册表：PDF→结构化标签映射、疾病关键词归一、select_guidelines_by_profile 两阶段检索的阶段1
├── tracing_helper.py            # RAG 节点追踪辅助：@traced_node 装饰器为节点包装 OpenTelemetry span（耗时/输入/输出）
│
├── loaders/                     # 文档加载器
│   ├── __init__.py
│   ├── pdf_loader.py            # PDF 加载器：基于 PyMuPDF(fitz) 提取文本
│   └── audio_loader.py          # 音视频加载器：基于 OpenAI Whisper 转写，支持多种格式与模型大小，含 ffmpeg 路径检测
│
└── nodes/                       # RAG 管道节点
    └── __init__.py              # 【核心】RAG 管道节点定义：意图识别/Query改写/SQL检索/向量检索/生成/评估/计划生成/
                                   安全检查/fusion/追问/信息收集，含用户画像提取与元数据过滤(_build_metadata_filter)
```

**核心文件说明**：

#### [graph_builder.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/core/graph_builder.py)
LangGraph 状态机编排核心，定义 RAG 管道完整状态流转图：
- **节点注册**：把 nodes/__init__.py 中的节点函数加入图
- **普通边**：线性流转（如 safety_check → intent_recognizer）
- **条件边**：三个路由函数
  - `_route_after_safety`：安全护栏拦截 → END
  - `_route_after_intent`：按意图分流到 SQL/向量/混合/计划路径
  - `_route_after_evaluator`：评估不通过 → Query 改写循环

**完整流程**：
```
START → 安全护栏 → 意图识别 → Query改写 → (条件分流)
                                                ↓
        ┌───────────────┬───────────────┬───────────────┐
        ↓               ↓               ↓               ↓
    SQL检索          向量检索        混合检索        闲聊直答
        ↓               ↓               ↓
        └───────→ 评估 ←─┴───────────────┘
                    ↓
              评估通过？──No──→ Query改写(最多2次)
                    ↓ Yes
                RRF融合
                    ↓
                答案生成
                    ↓
                  END
```

#### [safety_checker.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/core/safety_checker.py)
安全护栏模块，双重校验机制：
1. **正则规则快筛**（<1ms，确定性高，12 类规则）
2. **LLM 语义慢审**（处理隐晦/变体表达）

**拦截类别**：处方药/药物推荐、极端饮食方式、疾病诊断/治疗方案

**热更新**：规则外置到 `config/safety_rules.yaml`，通过 `safety_rule_loader` 加载，mtime 检测自动生效

#### [nodes/__init__.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/core/nodes/__init__.py)
RAG 管道 11 个核心节点定义：

| 节点 | 职责 |
|------|------|
| `safety_check_node` | 安全校验（正则+LLM） |
| `intent_recognizer_node` | 意图识别（含关键词词库）+ 用户画像信息抽取 |
| `info_collector_node` | 信息完整性检查 + 指南匹配 |
| `query_rewriter_node` | Query 改写（同义词/扩写） |
| `sql_retriever_node` | SQL 食物检索 |
| `vector_retriever_node` | 向量检索（两阶段过滤） |
| `fusion_node` | RRF 融合多路结果 |
| `evaluator_node` | 评估检索质量，决定改写/追问/生成 |
| `generator_node` | LLM 生成回答（含风格指令注入） |
| `plan_generator_node` | 生成结构化饮食计划 |
| `clarification_node` | 追问节点（信息缺失时） |

**辅助函数**：`_extract_age/_region/_gender/_weight/_height_from_query`、`_build_metadata_filter`、`_rerank_results_by_metadata`

#### [guideline_registry.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/core/guideline_registry.py)
两阶段检索的「阶段1：指南路由」数据底座：
- 维护 `GUIDELINE_REGISTRY`（8 份主体食养指南的结构化标签映射）
- `match_guideline(file_name)`：PDF 文件名 → 注册表条目
- `select_guidelines_by_profile(profile)`：按用户画像选指南集合供阶段2过滤
- `build_guide_catalog_chunks()`：生成 guide_catalog 摘要 chunk 参与语义匹配
