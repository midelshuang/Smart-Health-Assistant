## 🚨 1.4 "BM25 关键词检索" —— 实际是 ILIKE 模糊匹配

**代码位置**：
- [src/repositories/chunk_repository.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/repositories/chunk_repository.py#L139) 注释写 "BM25 风格"
- [src/repositories/chunk_repository.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/repositories/chunk_repository.py#L167-L169) 实际实现：`CASE WHEN content ILIKE :exact THEN 100 ELSE 0 END` + `CASE WHEN content ILIKE :kw_{i} THEN 10 ELSE 0 END`
- [README.md](file:///G:/PyCharmMiscProject/HealthAI-Platform/README.md#L22) 写 "PostgreSQL BM25 关键词检索"
- 全项目无 `tsvector`、`tsquery`、`ts_rank`、`pg_trgm` 的使用

**问题描述**：BM25 是基于 TF-IDF + 文档长度归一化的特定算法。代码实际用的是 PostgreSQL 的 `ILIKE` 模式匹配 + 硬编码分数（精确匹配 100 分，关键词匹配 10 分），这不是 BM25。真正的 PostgreSQL BM25 要么用 `tsvector`/`tsquery` + `ts_rank_cd`，要么用 `pg_bm25` 扩展，要么用 Elasticsearch。

**面试官可能怎么问**：
- "BM25 公式你写一下？k1 和 b 参数你设的多少？"
- "PostgreSQL 怎么做 BM25？用的 tsvector 还是 pg_trgm？"
- "你的 BM25 和向量检索的分数怎么归一化的？"

**建议回答**：诚实说"实际实现是 ILIKE 模糊匹配 + 加权打分，不是严格 BM25 算法。当时为了快速实现 MVP 没上 tsvector，后续可以升级。README 写 BM25 是不准确的，应该改成'关键词检索'。" 这是技术债，承认即可。

**代码位置**：[src/services/feedback_service.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/services/feedback_service.py#L77-L117)

## ⚠️ 2.5 Embedding 失败静默返回零向量（数据污染风险）

**代码位置**：[src/core/embedding.py](file:///G:/PyCharmMiscProject/HealthAI-Platform/src/core/embedding.py#L168-L178)

**问题描述**：`_request_embedding` 在 HTTPError/URLError/Exception 时返回 `[[0.0] * dim for _ in texts]`（零向量）。如果入库时 Embedding API 挂了，会写入一批零向量到 ChromaDB，这些向量会和所有查询向量计算相似度，污染检索结果。而且 `similarity = 1.0 - distance`，零向量之间的 cosine distance 是 0，相似度是 1.0（满分），会排在最前面。

**面试官可能怎么问**：
- "Embedding API 挂了你的系统会怎样？"
- "零向量入库后对检索有什么影响？"

## 💡 3.1 TDEE 公式混合使用 Mifflin-St Jeor + Harris-Benedict 活动系数

## 💡 3.5 RRF 的 vector_doc_key 用 Python hash() 有进程随机性
