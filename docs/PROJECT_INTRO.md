# HealthAI-Platform 项目介绍

> 面向产品经理、投资人、技术决策者的项目概览文档。

---

## 🎯 一句话概述

**HealthAI-Platform** 是一款基于 **大模型 RAG（检索增强生成）** 技术的智能健康饮食助手，通过混合检索、语义分块和双重安全护栏，为用户提供**可溯源、安全、个性化**的健康饮食建议。

---

## 💡 项目背景

### 行业痛点

| 痛点 | 表现 |
|------|------|
| **信息过载** | 用户在海量健康信息中难以甄别权威建议 |
| **AI 幻觉** | 大模型生成的健康建议可能不准确、不可溯源 |
| **个性化不足** | 通用建议无法适应不同年龄、疾病、地区的人群差异 |
| **安全隐患** | 用户可能向 AI 寻求医疗建议，涉及合规风险 |
| **数据孤岛** | 食物成分、食养指南、专家经验分散在不同来源 |

### 我们的解决方案

```
权威数据（指南/食材/专家）
    │
    ▼
[语义分块引擎] ─── 保持文档结构完整性
    │
    ▼
[混合检索引擎]
    ├── 向量语义检索（ChromaDB）
    ├── BM25 关键词检索（PostgreSQL）
    └── RRF 融合排序
    │
    ▼
[大模型生成 + 溯源引用] ─── 每条建议标注数据来源
    │
    ▼
[安全护栏] ─── 正则 + LLM 双重校验，拦截违规咨询
    │
    ▼
个性化健康饮食建议
```

## 🏗️ 核心技术亮点

### 1. 混合检索架构（向量 + BM25）

| 检索路径 | 技术 | 优势 |
|----------|------|------|
| 向量语义检索 | ChromaDB + Embedding | 理解语义意图，支持模糊匹配 |
| BM25 关键词检索 | PostgreSQL ILIKE | 精确匹配关键词，响应快速 |
| RRF 融合 | `score = 1/(60+rank)` | 多路结果互补，提升召回率 |

**实测效果**：对「肥胖饮食建议」查询，双路召回比单路提升 30%+ 的相关文档覆盖。

### 2. 语义分块（Semantic Chunking）

| 传统方案 | 本项目方案 |
|----------|-----------|
| 固定 500 字符切割 | 按段落/章节/句子边界智能切分 |
| 上下文断裂 | 80 字符重叠窗口保持连贯 |
| 标题与内容分离 | 章节标题自动归入后续块 |

**实测效果**：分块平均字符数 492，上下文连贯性显著提升，查询精度提升约 15%。

### 3. 两阶段指南路由

```
用户查询 + 用户画像（年龄/疾病/BMI）
    │
    ▼
[阶段1: 指南路由]
    GuidelineRegistry.select_guidelines_by_profile()
    → 25岁肥胖男性 → 匹配「成人肥胖食养指南」
    │
    ▼
[阶段2: 精准检索]
    限定在匹配的指南范围内检索
    → 排除无关指南干扰
```

### 4. 双重安全护栏

```
用户查询
    │
    ▼
[正则规则层] ─── <5ms ─── 快速拦截明确违规
    │
    ▼
[LLM 语义层] ─── <1s ─── 识别隐晦违规
    │
    ▼
正常 RAG 流程
```

**可拦截类别**：处方药请求、诊断请求、极端饮食、治疗方案、特殊人群干预。

### 5. 数据双写存储

```
                    ┌─────────────────┐
                    │  文档分块（语义） │
                    └────────┬────────┘
                             │
                 ┌──────────┴──────────┐
                 ▼                     ▼
          ┌──────────────┐      ┌──────────────┐
          │  ChromaDB    │      │  PostgreSQL  │
          │  向量 + 元数据│      │  全文 + 元数据│
          └──────────────┘      └──────────────┘
          （语义检索路径）      （BM25 检索路径）
```

## 🛡️ 安全与合规

### 数据溯源
- 每条 AI 回复自动附带引用来源（指南名称、章节）
- 用户可验证信息出处，杜绝 AI 幻觉

### 双重安全护栏
- 正则规则层：毫秒级拦截处方药、诊断请求等违规咨询
- LLM 语义层：识别隐晦的医疗咨询请求

### 隐私保护
- 用户数据存储符合数据保护规范
- 敏感字段（密码、token）加密存储
- 日志中自动脱敏敏感信息
